Scopes control what your credential can access. Each endpoint requires a specific scope. If your credential doesn't carry it, the API returns `403 Forbidden`. It never returns partial data or silently omits fields. Designing around scopes from the start keeps your integration predictable and limits the blast radius if a token leaks.

## Available scopes

| Scope               | Required for                                              | Grants                                       |
| ------------------- | --------------------------------------------------------- | -------------------------------------------- |
| `profile.read`      | `GET /profile`                                            | Public profile, username and plan            |
| `services.read`     | `GET /services`, `GET /services/{id}`                     | Your default and single-use services         |
| `services.write`    | `POST /services`, `PATCH /services/{id}`, `DELETE /services/{id}` | Create, edit and delete your services and single-use links |
| `availability.read` | `GET /availability`                                       | Available time slots                         |
| `bookings.read`     | `GET /bookings`, `GET /bookings/{id}`                     | Existing bookings                            |

## Plans

Every scope works on every plan, Free included. The API follows the plan limits of the Tikk account it acts for, not of the developer who built the app. Creating a service beyond the Free limit, for example, returns `403` with `"error": "plan_required"`, just like it would be refused in the app. See [Errors](/api-reference/errors#plan-required-403).

To adapt your UI up front, read `plan` from [`GET /profile`](/api-reference/profile/get-profile).

## API keys

When you create a key under **Settings → API Keys**, you choose which scopes it carries. Pick at least one. A key can only call endpoints for the scopes you gave it. You can have up to 10 active keys.

## OAuth tokens

When building a partner app, request only the scopes your integration actually needs. You choose your app's scopes when you register it in the [developer portal](https://developer.tikk.chat). Specify them in the `scope` query parameter on the authorization URL as a space-separated list:

```text
https://app.tikk.chat/oauth/authorize
  ?client_id=YOUR_CLIENT_ID
  &redirect_uri=https://yourapp.com/callback
  &response_type=code
  &scope=profile.read bookings.read
```

The user sees exactly which scopes your app is requesting on Tikk's consent screen. The resulting access token only carries the scopes you requested, even if the user's account has broader permissions.

## Missing scope response

If you call an endpoint without the required scope, the API responds with `403 Forbidden` and the following body:

```json
{
  "message": "Missing required scope.",
  "scopes": ["bookings.read"]
}
```

`scopes` lists the scope or scopes the endpoint needs. Check the [Errors](/api-reference/errors) page for the full list of error codes and their meanings.

<Tip>
  Request the minimum scopes your integration needs. Fewer scopes means smaller
  impact if a token leaks. An attacker with a `profile.read`-only token can't
  reach bookings data or change your services.
</Tip>
