---
title: "PATCH /services/{id}. Edit a default service"
sidebarTitle: "PATCH /services/{id}"
description: "Change only the fields you send on a default service. Single-use services can't be edited."
---

The `PATCH /services/{id}` endpoint edits a default service and returns it. Only the fields you send change. `durations` and `location` are replaced as a whole when sent.

A single-use service can't be edited. Delete it and create a new one.

## Endpoint

```text
PATCH https://app.tikk.chat/api/v1/services/{id}
```

**Required scope:** `services.write`

## Path parameters

<ParamField path="id" type="integer" required>
  The `id` of the default service.
</ParamField>

## Body parameters

All fields are optional. They take the same values as when you [create a default service](/api-reference/services/create-service#default-service): `title`, `description`, `slug`, `durations`, `is_group`, `max_attendees`, `requires_approval` and `location`.

The same plan rules apply. On Free, a custom `slug` is ignored, `requires_approval` stays off and `is_group` returns `422`.

## Example request

```bash
curl -X PATCH https://app.tikk.chat/api/v1/services/48213 \
  -H "Authorization: Bearer {YOUR_API_KEY}" \
  -H "Accept: application/json" \
  -H "Content-Type: application/json" \
  -d '{"title": "Discovery call", "durations": [{ "minutes": 45, "price": 5000 }]}'
```

## Response

Status `200 OK`. The body is `{ "data": ... }` with the default service described on [Get service](/api-reference/services/get-service#response-schema).

## Errors

| Status | Meaning                                                                                         |
| ------ | ----------------------------------------------------------------------------------------------- |
| `401`  | Missing or invalid credential.                                                                  |
| `403`  | Your credential does not have the `services.write` scope.                                       |
| `404`  | No service with this id on your account.                                                        |
| `409`  | The service is single-use. Single-use services can't be edited.                                 |
| `422`  | A field failed validation, for example a `slug` already used by another service.                |
| `429`  | Rate limit exceeded. Back off and retry after the period indicated in the `Retry-After` header. |
