---
title: "DELETE /services/{id}. Delete a service"
sidebarTitle: "DELETE /services/{id}"
description: "Delete a default service, or a single-use service that hasn't been booked."
---

The `DELETE /services/{id}` endpoint deletes a service of either type.

- A **default** service is deleted. If it was the highlighted one, your oldest remaining service becomes highlighted, as in Tikk.
- A **single-use** service is deleted only while it hasn't been booked. A booked one stays: it's the booking's record of how it was made.

## Endpoint

```text
DELETE https://app.tikk.chat/api/v1/services/{id}
```

**Required scope:** `services.write`

## Path parameters

<ParamField path="id" type="integer" required>
  The service `id`.
</ParamField>

## Example request

```bash
curl -X DELETE https://app.tikk.chat/api/v1/services/73920 \
  -H "Authorization: Bearer {YOUR_API_KEY}"
```

## Response

Status `204 No Content` with an empty body.

## Errors

| Status | Meaning                                                                                         |
| ------ | ----------------------------------------------------------------------------------------------- |
| `401`  | Missing or invalid credential.                                                                  |
| `403`  | Your credential does not have the `services.write` scope.                                       |
| `404`  | No service with this id on your account.                                                        |
| `409`  | The single-use service has been booked and can't be deleted.                                    |
| `429`  | Rate limit exceeded. Back off and retry after the period indicated in the `Retry-After` header. |
