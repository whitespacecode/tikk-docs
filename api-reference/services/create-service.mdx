---
title: "POST /services. Create a service"
sidebarTitle: "POST /services"
description: "Create a default service, or a single-use service for one person. Returns the service with status 201."
---

The `POST /services` endpoint creates a service and returns it. `type` is required and decides which fields apply:

- `default` creates a permanent booking page, with the same fields the API returns for one.
- `single_use` creates a private booking link for one person. Send the person its `url`.

Booking limits, custom hours, `is_active` and choosing the highlighted service aren't writable through the API. Set those in Tikk.

## Endpoint

```text
POST https://app.tikk.chat/api/v1/services
```

**Required scope:** `services.write`

## Body parameters

<ParamField body="type" type="string" required>
  `default` or `single_use`.
</ParamField>

### Default service

<ParamField body="title" type="string" required>
  Service name, at most 50 characters.
</ParamField>

<ParamField body="durations" type="array" required>
  At least one duration. Each is an object with `minutes` (`5` to `480`, no repeats) and `price` (integer in minor currency units, `0` to `999999`, or `null` for free). `1500` is €15.00.
</ParamField>

<ParamField body="description" type="string">
  Description shown on the booking page, at most 500 characters.
</ParamField>

<ParamField body="slug" type="string">
  Lowercase letters, digits and single hyphens, at most 100 characters, unique among your services. Custom slugs need Pro. On Free, the slug is generated from the title and a `slug` you send is ignored.
</ParamField>

<ParamField body="is_group" type="boolean">
  Several people can book the same slot. Needs Pro.
</ParamField>

<ParamField body="max_attendees" type="integer">
  Seat cap, `2` to `50`. Required when `is_group` is `true`.
</ParamField>

<ParamField body="requires_approval" type="boolean">
  `true` if you accept each booking by hand. Manual approval needs Pro. On Free, bookings are always accepted automatically.
</ParamField>

<ParamField body="location" type="object">
  An object with `type` (a location key, such as `video`) and optional `address` (at most 100 characters).
</ParamField>

### Single-use service

<ParamField body="service" type="integer">
  The `id` of one of your default services to copy. The link offers that service's durations and location. Can't be combined with `duration`. An id that isn't one of your bookable default services returns `422`.
</ParamField>

<ParamField body="title" type="string">
  Name of the link, at most 50 characters. Required without `service`. With `service` it replaces the default title, "{service} for {contact_name}".
</ParamField>

<ParamField body="description" type="string">
  Note shown at the top of the booking page, at most 500 characters.
</ParamField>

<ParamField body="contact_name" type="string">
  Who the link is for, at most 100 characters.
</ParamField>

<ParamField body="contact_email" type="string">
  Email address of the contact. When given, the contact is saved to your contacts.
</ParamField>

<ParamField body="expires_in_days" type="integer">
  Days until the link expires. Between `1` and `365`. Defaults to `30`.
</ParamField>

<ParamField body="duration" type="integer">
  Meeting length in minutes, between `5` and `480`. Defaults to `30`. Only without `service`.
</ParamField>

## Example requests

A default service:

```bash
curl -X POST https://app.tikk.chat/api/v1/services \
  -H "Authorization: Bearer {YOUR_API_KEY}" \
  -H "Accept: application/json" \
  -H "Content-Type: application/json" \
  -d '{
    "type": "default",
    "title": "Intro call",
    "durations": [{ "minutes": 30, "price": null }, { "minutes": 60, "price": 7500 }],
    "location": { "type": "video" }
  }'
```

A single-use service copied from a default one:

```bash
curl -X POST https://app.tikk.chat/api/v1/services \
  -H "Authorization: Bearer {YOUR_API_KEY}" \
  -H "Accept: application/json" \
  -H "Content-Type: application/json" \
  -d '{"type": "single_use", "service": 48213, "contact_name": "Sam Smith", "contact_email": "sam@example.com"}'
```

## Response

Status `201 Created`. The body is `{ "data": ... }` with the service described on [Get service](/api-reference/services/get-service#response-schema).

```json
{
  "data": {
    "type": "single_use",
    "id": 73920,
    "title": "Intro call for Sam Smith",
    "description": null,
    "status": "open",
    "url": "https://tikk.chat/jane/Xk3pQ9aB2c/intro-call-for-sam-smith",
    "contact": { "name": "Sam Smith", "email": "sam@example.com" },
    "durations": [
      { "minutes": 30, "price": null, "currency": "EUR" },
      { "minutes": 60, "price": null, "currency": "EUR" }
    ],
    "expires_at": "2026-10-31T09:00:00+00:00",
    "created_at": "2026-10-01T09:00:00+00:00"
  }
}
```

## Errors

| Status | Meaning                                                                                                                                   |
| ------ | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `401`  | Missing or invalid credential.                                                                                                            |
| `403`  | Your credential does not have the `services.write` scope. Creating a default service beyond your plan's limit returns `plan_required`. |
| `422`  | A field failed validation, for example a missing `type`, no `title`, `is_group` on Free, or both `service` and `duration`.                |
| `429`  | Rate limit exceeded. Back off and retry after the period indicated in the `Retry-After` header.                                           |

<Note>
  A Free account can have one default service. Creating another returns `403`
  with `"error": "plan_required"`, the same body as a Pro scope. See
  [Scopes](/api-reference/scopes#plans).
</Note>
